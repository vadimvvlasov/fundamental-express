# ТЗ на Шаг 1: Модернизация Ядра (Ordinary) и Проектирование Модульного Каркаса

## 1. Назначение документа
Настоящее техническое задание (ТЗ) описывает требования к реализации **Шага 1** масштабной реструктуризации аналитической платформы `fundamental-express`.
Цель этого шага — перевод монолитного скрипта анализа в гибкую модульную архитектуру на основе классов (паттерн «Фабрика») [271, 272] и глубокая модернизация логики оценки обычных коммерческих компаний (Ordinary Companies) [2, 57, 264].

Разработчик (кодинг-агент) должен строго следовать описанной математике, структурам данных и архитектурным шаблонам.

## 2. Архитектура модульного каркаса (Паттерн «Фабрика»)
Текущая монолитная структура заменяется на объектно-ориентированную иерархию [271, 272]. Класс-роутер определяет отраслевую принадлежность тикера и возвращает нужный объект-анализатор.

### 2.1. Иерархия классов

```python
from abc import ABC, abstractmethod

class BaseAnalyzer(ABC):
    def __init__(self, ticker: str, args):
        self.ticker = ticker
        self.args = args
        self.raw_data = None
        self.metrics = {}
        self.fair_value_results = {}

    @abstractmethod
    def fetch_data(self) -> bool:
        """Скачивание данных через yfinance с обработкой ретраев и ошибок."""
        pass

    @abstractmethod
    def calculate_metrics(self) -> dict:
        """Расчет чеклиста 'грехов' и специфических финансовых показателей."""
        pass

    @abstractmethod
    def calculate_fair_value(self) -> dict:
        """Оценка справедливой стоимости акции (DCF, DDM или NAV)."""
        pass

    @abstractmethod
    def generate_markdown_report(self) -> str:
        """Генерация текстовой версии отчета в формате Markdown."""
        pass

    @abstractmethod
    def generate_pdf_report(self, output_path: str):
        """Отрисовка PDF-отчета на базе ReportLab с поддержкой кириллицы."""
        pass
```

### 2.2. Роутинг и Фабрика (`AnalyzerFactory`)
Фабрика должна анализировать поля `sector` и `industry` из метода `ticker.info` библиотеки `yfinance` [271, 272]:

1.  **Банковский сектор (`BankAnalyzer`):**
    *   *Критерий:* `info.get('sector') == 'Financial Services'` и `info.get('industry')` содержит подстроку `Bank` или `Capital Markets` или `Insurance` [271].
    *   *На Шаге 1:* Создается класс-заглушка `BankAnalyzer`, унаследованный от `BaseAnalyzer`. При попытке запустить расчет без флага `--force` он падает с понятным исключением: *"Сектор банков находится в разработке (Шаг 2). Запустите с флагом --force для базового отчета"* [255, 272].
2.  **Трасты недвижимости (`ReitAnalyzer`):**
    *   *Критерий:* `info.get('industry')` содержит подстроку `REIT` или `Real Estate Investment Trust` [191, 271].
    *   *На Шаге 1:* Создается класс-заглушка `ReitAnalyzer`. Без флага `--force` он падает с исключением: *"Сектор REIT находится в разработке (Шаг 3). Используйте --force для базового отчета"* [272].
3.  **Обычные компании (`OrdinaryAnalyzer`):**
    *   *Критерий:* Все остальные случаи [272].
    *   *На Шаге 1:* Полнофункциональный рабочий класс, реализующий модернизированные формулы [264].

## 3. Модернизация модуля обычных компаний (`OrdinaryAnalyzer`)

### 3.1. Двухуровневая модель чеклиста «грехов» (Модернизированная)
Вместо плоской системы весов внедряется гибкая система баллов с учетом новых рыночных индикаторов (размытие, байбэк) [55, 56, 107] и динамическим обходом жестких условий ликвидности [181, 182, 281].

#### А. Критические грехи (4 пункта)
Если срабатывает **хотя бы один** критический грех, итоговый вердикт безоговорочно становится **🔴 ПРОПУСТИТЬ (SKIP)**, независимо от остальных баллов [265]:

1.  **Сжигание кэша (FCF ≤ 0):** `Free Cash Flow` за последний доступный год равен или меньше нуля [113, 164, 265].
2.  **Отрицательный акционерный капитал:** `Shareholders Equity` за последний год $\le 0$ [67, 265].
3.  **Долгосрочная неплатежеспособность (Insolvency):**
    *   $\text{Долгосрочные Активы} - \text{Goodwill} < \text{Долгосрочные Обязательства}$ [80, 81, 265, 282].
    *   *Формула:* `(Total Non-Current Assets - Goodwill) < Total Non-Current Liabilities` [80, 81, 265, 282].
4.  **Дефицит ликвидности (Модернизированный `Current Ratio`):**
    *   *Базовое правило:* `Current Ratio = Total Current Assets / Total Current Liabilities < 1.0` [182, 265, 280].
    *   *Смарт-исключение (Интеллектуальный обход):* Если `Current Ratio < 1.0`, но при этом **компания стабильно генерирует свободный денежный поток (`FCF > 0`)** и **объем свободных денежных средств на балансе (`Cash and Cash Equivalents`) превышает сумму краткосрочного долга (`Current Debt / Short Term Debt`)**, данный грех **НЕ считается критическим** [181, 182, 281]. Вместо этого он переносится в категорию второстепенных грехов с пенальти-весом **1.0** [182, 266].

#### Б. Второстепенные грехи (11 пунктов со взвешенным баллом)
Если критических грехов нет, вердикт рассчитывается на основе суммы баллов по второстепенным грехам [266, 267]:

| Вес балла | Грех | Алгоритм расчета |
| :--- | :--- | :--- |
| **1.0** | Падение акционерного капитала | `Equity(Year_N) < Equity(Year_N-1)` [57, 266] |
| **1.0** | Падение FCF YoY | `FCF(Year_N) < FCF(Year_N-1)` (если оба значения $>0$) [57, 113, 266] |
| **1.0** | Падение выручки | `Revenue(Year_N) < Revenue(Year_N-1)` [57, 265, 266] |
| **1.0** | Падение операционной прибыли | `Operating Income(Year_N) < Operating Income(Year_N-1)` [57, 266] |
| **0.5** | Ухудшение Current Ratio | `Current Ratio(Year_N) < Current Ratio(Year_N-1)` **ТОЛЬКО** если текущий `Current Ratio < 2.0` [181, 182, 266] |
| **0.5** | Снижение валовой маржи | `Gross Margin(Year_N) < Gross Margin(Year_N-1)` [58, 184, 266] |
| **0.5** | Снижение опер. маржи | `Operating Margin(Year_N) < Operating Margin(Year_N-1)` [58, 266] |
| **0.3** | Падение чистой прибыли | `Net Income(Year_N) < Net Income(Year_N-1)` (наиболее волатильная метрика) [58, 266] |
| **0.3** | Снижение чистой маржи | `Net Margin(Year_N) < Net Margin(Year_N-1)` [266] |
| **0.5** | **Размытие долей акционеров (Новый)** | Средневзвешенное число акций в обращении `Diluted Average Shares` выросло год-к-году более чем на **1.5%** [53, 56]. |
| **-0.5** | **Бонус за выкуп акций (Новый)** | Средневзвешенное число акций `Diluted Average Shares` снизилось год-к-году более чем на **1.5%** (активный байбэк) [55, 107]. **Балл вычитается** из общей суммы второстепенных грехов! |

#### В. Итоговый Вердикт (при отсутствии критических грехов):
*   Сумма баллов **$\le 1.0$** — 🟢 **КУПИТЬ (BUY)** [267]
*   Сумма баллов **от 1.01 до 2.5** — 🟡 **НАБЛЮДАТЬ (WATCH)** [267]
*   Сумма баллов **$> 2.5$** — 🔴 **ПРОПУСТИТЬ (SKIP)** [267]

### 3.2. Модернизация DCF справедливой стоимости (CAPM / WACC)

```
                       [ DCF Модель Оценки ]
                                 │
     ┌───────────────────────────┴───────────────────────────┐
     ▼                                                       ▼
[Шаг 1. Расчет WACC]                               [Шаг 2. Проекция FCF]
  Ke = Rf + Beta * ERP (CAPM)                        Прогноз на 5 лет по CAGR
  или Ke = --required-return                         Дисконтирование по WACC
  Kd_after_tax = Kd * (1 - T)                                │
  WACC = (E/(D+E))*Ke + (D/(D+E))*Kd_after_tax               ▼
     │                                             [Шаг 3. Терминальная Стоимость]
     │                                               TV = FCF5*(1+g) / (WACC - g)
     │                                                       │
     └───────────────────────────┬───────────────────────────┘
                                 ▼
                     [Шаг 4. Стоимость Компании]
                       EV = Sum(PV_FCF) + PV_TV
                       Equity Value = EV - Net Debt
                       Fair Price = Equity Value / Shares Outstanding
```

#### А. Индивидуальная требуемая доходность инвестора (`--required-return`)
В кодинг-агент должен добавить параметр командной строки `--required-return` (тип `float`, диапазон `0.05`–`0.25`, по умолчанию выключен) [151, 161]:
*   Если параметр **не передан**, стоимость собственного капитала ($K_e$) рассчитывается по стандартной формуле CAPM:
    $$K_e = R_f + \beta \times ERP$$
    где $R_f = 4.0\%$ (безрисковая ставка), $ERP = 5.0\%$ (премия за риск акций), $\beta$ — бета-коэффициент из `yfinance` (если нет беты, дефолт $\beta = 1.1$) [274, 276].
*   Если параметр **передан** (например, `--required-return 0.12`), то расчет CAPM отключается и $K_e$ принудительно приравнивается к значению инвестора: $K_e = 12\%$ [150, 151, 161]. Это задает персональный «запас прочности» инвестора [9, 11, 21].

#### Б. Расчет WACC и дисконтирование
*   **Стоимость долга ($K_d$):** Зафиксирована на уровне $4.5\%$ до налогов [262, 274].
*   **Налоговая ставка ($T$):** Зафиксирована на уровне $21\%$ [262, 274].
*   **Веса капитала:** $E$ (Рыночная капитализация) и $D$ (Interest-bearing Debt / процентный долг). Если долгосрочный процентный долг отсутствует на балансе, использовать Total Debt включая аренду как фоллбэк [274, 275].
*   **Дисконтирование:** Терминальный рост ($g$) фиксирован на уровне $2.5\%$ [262, 274]. Ограничение на темп роста CAGR FCF на прогнозные 5 лет — не более $15\%$ [262, 274].

## 4. Требования к верстке и формированию отчетов

1.  **Поддержка кириллицы в PDF:** Скрипт должен гарантировать безопасную регистрацию шрифта `DejaVu Sans` (и его полужирного начертания `DejaVuSans-Bold`) по абсолютному пути `/usr/share/fonts/truetype/dejavu/DejaVuSans.ttf` [253]. Если файл шрифта отсутствует, делать плавный фоллбэк на `Helvetica` с выводом предупреждения в терминал [253].
2.  **Двуязычность и мета-данные:** Все заголовки, описания «грехов» и финальные выводы в PDF и Markdown генерируются на русском языке. Финансовые метрики и названия строк баланса могут дублироваться на английском для прозрачной сверки с первоисточниками [36, 129].
3.  **Исключение путей из логов:** Отчеты должны генерироваться в директорию `output/` [253]. В терминал выводится краткое саммари со справедливой ценой и итоговым вердиктом (BUY/WATCH/SKIP), без упоминания абсолютных путей файловой системы.
