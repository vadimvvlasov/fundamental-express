# ТЗ на Шаг 2: Реализация Специализированного Модуля Анализа Банков (BankAnalyzer)

## 1. Назначение документа
Настоящее техническое задание (ТЗ) описывает требования к реализации **Шага 2** модульной модернизации аналитической платформы `fundamental-express`.
Цель этого шага — заменить временную заглушку-делегата `BankAnalyzer` на полнофункциональный аналитический модуль, адаптированный под особенности финансовой и регуляторной отчетности коммерческих банков [117, 118].

Все формулы ликвидности и классического DCF (WACC, Enterprise Value, Net Debt), используемые для обычных коммерческих предприятий, математически некорректны для банковского сектора [121, 131, 144]. Кодинг-агент должен реализовать специализированную структуру баланса, скоринга и оценки справедливой стоимости банков, строго следуя описанной ниже математической и логической модели [117, 121, 131].

## 2. Архитектура и интеграция в роутер

В рамках Шага 1 был создан класс-скелет `BankAnalyzer(BaseAnalyzer)`. В Шаге 2 этот класс должен быть наполнен реальным функционалом, а отраслевой предохранитель в `AnalyzerFactory` и `portfolio_analyzer.py` должен быть обновлен.

### 2.1 Изменения в роутинге (AnalyzerFactory)
1.  **Снятие блокировки (Native Support):**
    *   Банковский сектор теперь поддерживается нативно. Метод `check_sector_suitability()` больше не должен вызывать исключение `UnsupportedSectorError` для банков.
    *   При запуске анализа по банку (например, `JPM` или `BAC`) без флага `--force` система должна **успешно выполнять расчеты** через `BankAnalyzer`.
2.  **Обратная совместимость флага `--force`:**
    *   Если пользователь принудительно передает флаг `--force` для банковского тикера, система по-прежнему должна выполнять специализированный банковский анализ через `BankAnalyzer`. Наличие флага `--force` больше не требуется, но его передача не должна ломать запуск.

### 2.2 Изменения в портфельном анализе (`portfolio_analyzer.py`)
1.  **Удаление fail-fast блокировки:**
    *   Удалить проверку, которая прерывала запуск всего портфеля, если в нем обнаруживался банк без флага `--force`. Теперь портфельный анализатор свободно пропускает банковские тикеры через `AnalyzerFactory`.
2.  **Специфическая строка в сводной таблице:**
    *   Для банковских тикеров в сводной таблице портфеля (консольной, Markdown и PDF):
        *   Вместо `Current Ratio` выводится показатель `LTD (Loan-to-Deposit)` [139].
        *   Вместо `FCF` выводится `Net Interest Income (NII)` (Чистый процентный доход) [123].
        *   У банков отсутствует `Enterprise Value` и `Net Debt`, поэтому в столбцах долговой нагрузки выводится отношение `Total Debt / Shareholders Equity` [140, 142].

## 4. Специализированный чеклист «грехов» для банков

У банков оценивается динамика изменения ключевых статей баланса и эффективности работы процентного портфеля [121, 131].

### 4.1 Критические банковские грехи (Любой из них = 🔴 ПРОПУСТИТЬ / SKIP)
При срабатывании любого из этих пунктов итоговый вердикт безоговорочно становится `🔴 ПРОПУСТИТЬ`, а детальный скоринг по второстепенным грехам прерывается [264, 265].

1.  **Чистый процентный убыток:** Чистый процентный доход за последний год равен или меньше нуля ($NII \le 0$) [121, 122]. Банк привлекает депозиты под ставку более высокую, чем ставка размещения кредитов (разрушение бизнеса) [118, 121, 124].
2.  **Отрицательный регуляторный капитал:** Собственный акционерный капитал банка за последний доступный год равен или меньше нуля ($\text{Shareholders Equity} \le 0$) [67, 122]. Угроза немедленного отзыва лицензии регулятором.

### 4.2 Второстепенные банковские грехи (Суммируемый взвешенный балл)
Каждый сработавший триггер увеличивает итоговый штрафной балл на указанный вес. Сравнивается последний отчетный год с предыдущим (YoY) [264].

| Вес балла | Триггер (Грех) | Условие проверки в коде | Финансовое обоснование |
| :--- | :--- | :--- | :--- |
| **1.0** | **Падение процентного дохода** | $NII_{current} < NII_{prior}$ | Падение эффективности генерации основного процентного дохода [121, 123]. |
| **1.0** | **Опасный рост резервов** | $Provision_{current} > 1.15 \times Provision_{prior}$ | Резервы под ожидаемые дефолты выросли YoY более чем на **15%** (ухудшение качества кредитного портфеля) [121, 122, 137]. |
| **1.0** | **Размытие долей акционеров** | $\frac{Shares_{current}}{Shares_{prior}} > 1.015$ | Рост средневзвешенного числа акций YoY превысил **1.5%** [53, 56]. |
| **0.5** | **Дисбаланс Loan-to-Deposit (LTD)** | $LTD_{current} = \frac{NetLoans_{current}}{TotalDeposits_{current}}$<br>Триггер если: **$LTD_{current} > 100\%$** ИЛИ **$LTD_{current} < 60\%$** | При $LTD > 100\%$ банк выдал больше кредитов, чем имеет депозитов (риск дефицита ликвидности) [139, 140]. При $LTD < 60\%$ банк работает пассивно, "мертвые" депозиты не приносят доход [132]. |
| **0.5** | **Накопление мертвого кэша** | $Cash_{current} > 1.30 \times Cash_{prior}$<br>**И одновременно** кредитный портфель упал:<br>$NetLoans_{current} < NetLoans_{prior}$ | Банк боится выдавать кредиты реальному сектору и копит обесценивающийся кэш, снижая рентабельность [132]. |
| **0.5** | **Опережающий рост затрат** | $Growth_{OpEx} > Growth_{NetOpIncome}$<br>где:<br>$OpEx = non\_interest\_expense$<br>$NetOpIncome = NII + commissions\_income$ | Операционные расходы (зарплаты, офисы) растут быстрее основного операционного дохода (NII + Комиссии). Отрицательный JAWS-коэффициент [125, 127]. |
| **0.3** | **Падение комиссионных доходов** | $Commissions_{current} < Commissions_{prior}$ | Свидетельствует об оттоке клиентов или снижении транзакционной активности в банке [125, 126]. |
| **0.3** | **Падение чистой прибыли** | $NetIncome_{current} < NetIncome_{prior}$ | Общее снижение чистой прибыли за период после уплаты налогов [128]. |

*Специальный бонус:* Если банк проводит обратный выкуп акций (Buyback: число акций YoY сократилось более чем на **1.5%**), из итогового штрафного балла вычитается **-0.5 балла** (итоговый балл не может опуститься ниже 0.0) [55, 107].

### 4.3 Шкала Вердикта (при 0 критических грехов):
*   Сумма баллов **$\le 1.0$** — 🟢 **КУПИТЬ (BUY)** [267]
*   Сумма баллов **от 1.01 до 2.5** — 🟡 **НАБЛЮДАТЬ (WATCH)** [267]
*   Сумма баллов **$> 2.5$** — 🔴 **ПРОПУСТИТЬ (SKIP)** [267]

## 5. Оценка справедливой стоимости банков

Классический WACC и FCF-дисконтирование неприменимы к банкам [121, 131, 144]. `BankAnalyzer` должен реализовывать две альтернативные модели оценки, выбор между которыми зависит от наличия дивидендных выплат.

### 5.1 Выбор модели (Decision Tree)
1.  Если у банка за последний TTM-период сумма выплаченных дивидендов на акцию `Common Dividends Paid` $> 0$ (или `dividendYield` в `yfinance.info` $> 0$), система использует **Модель А: Dividend Discount Model (DDM)** [118].
2.  Если банк не выплачивает дивиденды (значение равно 0 или отсутствует), система переключается на **Модель Б: Рентабельность собственного капитала (ROE / P/B Model)**.

---

### 5.2 Модель А: Dividend Discount Model (DDM)

Оценка строится на дисконтировании прогнозного потока дивидендов на акцию ($DPS$) [118].

#### Шаг 1: Расчет темпа роста дивидендов (CAGR_div)
Рассчитывается геометрический темп роста выплаченных дивидендов на обыкновенную акцию ($DPS = \text{Common Dividends Paid} / \text{Diluted Shares}$) за доступные 4 года:
$$\text{CAGR\_div} = \left(\frac{DPS_{\text{last}}}{DPS_{\text{first}}}\right)^{\frac{1}{N}} - 1$$
*   **Ограничение (Clamping):** Темп роста жестко зажимается в диапазоне $[1.0\%, 8.0\%]$ (консервативный банковский рост) [262].
*   **Дефолт:** Если история дивидендов прерывиста, отрицательна на концах или недоступна, $\text{CAGR\_div}$ принимается равным **3.0%**.

#### Шаг 2: Расчет стоимости акционерного капитала ($K_e$)
Поскольку у банков отсутствует WACC, дисконтирование производится строго по стоимости собственного капитала ($K_e$) [274]:
*   Если передан CLI-параметр `--required-return`, то $K_e = \text{required\_return}$ (например, 12%) [290].
*   Если параметр не передан, рассчитывается по CAPM:
    $$K_e = R_f + (\beta \times ERP)$$
    где $R_f = 4.0\%$, $ERP = 5.0\%$, $\beta$ — бета из `yfinance` (если отсутствует, дефолт $\beta = 1.1$) [274, 276].
    *Диапазон ограничений для $K_e$ при расчете DDM: $[5.0\%, 15.0\%]$.*

#### Шаг 3: Прогнозирование и дисконтирование
Прогнозируется дивиденд на 5 лет вперед: $DPS_t = DPS_{\text{last}} \times (1 + \text{CAGR\_div})^t$.
$$\text{PV\_Dividends} = \sum_{t=1}^{5} \frac{DPS_t}{(1 + K_e)^t}$$

#### Шаг 4: Терминальная стоимость (Gordon Growth)
Терминальный рост ($g$) фиксируется на уровне **2.5%** [274].
$$TV = \frac{DPS_5 \times (1 + 0.025)}{K_e - 0.025}$$
$$\text{PV\_TV} = \frac{TV}{(1 + K_e)^5}$$

#### Шаг 5: Справедливая цена акции
$$\text{Fair Value per Share} = \text{PV\_Dividends} + \text{PV\_TV}$$

---

### 5.3 Модель Б: Рентабельность собственного капитала (ROE / P/B Model)

Модель оценивает банк на основе качества использования его акционерного капитала.

#### Шаг 1: Расчет базовых коэффициентов
1.  **Балансовая стоимость на обыкновенную акцию (BVPS):**
    $$BVPS = \frac{\text{Shareholders Equity}_{\text{latest}}}{\text{Shares Outstanding}_{\text{latest}}}$$
2.  **Рентабельность собственного капитала (ROE):**
    $$ROE = \frac{\text{Net Income}_{\text{latest}}}{\text{Shareholders Equity}_{\text{latest}}}$$
    *Если $ROE \le 0$ при положительном капитале, справедливая стоимость признается равной $0.1 \times BVPS$ (ликвидационная стоимость с дисконтом).*

#### Шаг 2: Расчет стоимости капитала ($K_e$)
Рассчитывается аналогично стоимости собственного капитала в п. 5.2 (CAPM или `--required-return`).

#### Шаг 3: Справедливая цена акции
$$\text{Fair Value per Share} = BVPS \times \frac{ROE}{K_e}$$
*Интуиция формулы:* Если банк зарабатывает $ROE > K_e$ (генерирует сверхдоходность), его справедливая цена должна быть выше балансовой стоимости ($P/B > 1.0$). Если $ROE < K_e$ (банк разрушает капитал), он должен торговаться с дисконтом к балансу ($P/B < 1.0$).

## 6. Требования к формированию отчета (PDF / Markdown)

Визуальный генератор не должен пытаться строить для банков графики WACC, Enterprise Value или Net Debt. Рендеринг должен быть адаптирован:

1.  **Метрики в шапке:** Вместо `Revenue` выводится `Net Interest Income (NII)`. Вместо `Current Ratio` выводится `Loan-to-Deposit Ratio (LTD)` [123, 139].
2.  **Раскрытие модели оценки:**
    *   Явно указывать выбранную модель: `Модель дисконтирования дивидендов (DDM)` или `Модель рентабельности капитала (ROE / P/B)`.
    *   Выводить промежуточные параметры: $K_e$, примененный темп роста $\text{CAGR\_div}$ (для DDM), либо $BVPS$ и $ROE$ (для модели ROE/PB).
3.  **Структурная таблица баланса:** В разделе финансового состояния выводить таблицу структуры кредитного портфеля и депозитной базы YoY (Net Loans, Provision Allowance, Total Deposits, LTD Ratio) [134, 137, 139].

## 7. Чек-лист тестирования для кодинг-агента

Перед сдачей кода агент обязан провести тесты на следующих тикерах:

1.  `JPM` (JPMorgan Chase) — флагманский диверсифицированный банк. Должна примениться **Модель DDM** (так как банк платит дивиденды) [118]. Тест без флага `--force` должен проходить успешно.
2.  `SIVBQ` (или любой дефолтный проблемный банк, например, с отрицательным ROE/NII) — проверка корректного срабатывания критических грехов и переключения на модель ROE/PB (если дивиденды обнулены).
3.  Регрессионный тест: `AAPL` и `MCD` должны проходить по стандартной `Ordinary` схеме, их результаты и вердикты не должны измениться ни на один байт.

Изменение — чисто аддитивное, не убирает ни одного из указанных в спецификации ключевых слов.
2.  **`SIVBQ` недоступен через `yfinance`** (как и `FRC`, `NYCB` — делистингованные/обанкротившиеся банки не отдают ни `financials`, ни `info.sector`). Пункт 2 чеклиста §7 закрыт синтетическими unit-тестами (`tests/test_bank_analyzer.py`), которые строят DataFrame вручную (тот же приём, что и в существующем `tests/test_verdict_scoring.py`) и покрывают: `NII ≤ 0` → критический грех, `Shareholders Equity ≤ 0` → критический грех, выбор модели ROE/PB при отсутствии дивидендов, дисконт при `ROE ≤ 0` (`0.1×BVPS`), а также все 8 второстепенных грехов §4.2 по отдельности и границы вердикта (1.0/2.5).
3.  **`Total Deposits` отсутствует в `yfinance` для JPM и BAC.** Ни один из трёх ключевых слов §3.2 (`Total Deposits`/`Deposits`/`Demand Deposits`), ни производные варианты не находят строку с депозитами в балансе крупных диверсифицированных банков — это ограничение самого `yfinance` (шаблон для банковских балансов не всегда включает разбивку по депозитам), не ошибка `find_row()`. Итог: `LTD Ratio` и связанный с ним грех `ltd_imbalance` для JPM/BAC честно показывают `N/A`/никогда не срабатывают, а не подставляют выдуманное число — в соответствии с общей философией проекта ("никогда не изобретать данные", см. `DataUnavailableError`).
